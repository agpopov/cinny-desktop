[cinny](https://github.com/cinnyapp/cinny) v4.12.7 с доработками для работы на Windows.

## Исправление непрочитанного — 4.12.8

- Автоматическое прочтение основной ленты и треда отправляет отметку в свою беседу.
  Достижение конца живой ленты работает и при старой отметке вне загруженной истории.
- «Mark As Read» и Esc отправляют общую отметку по последнему событию комнаты с сервера:
  она покрывает также треды, отсутствующие в текущем окне синхронизации.
- Счётчики очищаются после успешного ответа сервера. Новые сообщения во время запроса
  сохраняют непрочитанность; повторные запросы объединяются, ошибки допускают повтор.
- Все индикаторы пересчитываются по состоянию SDK после обработки событий, счётчиков,
  прочтения с других устройств, расшифровки и обновления тредов.
- Учитываются стабильные и MSC3381 опросы. Голос к корню опроса не заменяет отметку
  последнего ответа в треде. Учитывается последний ответ из сводки частично загруженного треда.
- Удаляется устаревшая линия New Messages. Фавикон, трей и панель задач показывают также
  непрочитанное без числового счётчика и очищаются вместе с комнатами.

Регрессионные тесты логики на настоящих моделях matrix-js-sdk: `cd cinny && npm run test:unread`.
Сквозные тесты на локальном Synapse: `APP_URL=http://localhost:8090 python3 tests/e2e/unread_receipts.py`.
Нужны Playwright с Chromium и тестовый Synapse на `127.0.0.1:8008` с открытой регистрацией.
`tests/e2e/spa_server.py` поддерживает переменную `PORT` для выбора свободного порта.

## Что изменено

### Уведомления Windows
- **Раньше уведомления не приходили вообще.** Cinny создавал их через браузерный `new Notification()`,
  а встроенный в Tauri WebView2 на Windows такие уведомления не показывает.
- Теперь уведомления нативные (WinRT toast), с аватаром отправителя, названием комнаты и текстом.
  Ответ в треде подписан «В треде: …».
- Клик по уведомлению разворачивает окно и открывает нужную комнату, а для ответа в треде — сам тред,
  прокрученный к сообщению.
- Решение «показывать или нет» принимается по push-правилам сервера, поэтому режимы комнат
  («только упоминания», «без звука») работают так же, как в Element.
- Тред беспокоит, только если вы его начали или писали в нём. Упоминание приходит всегда.
- Не показываются: свои сообщения, сообщения в открытой и активной комнате или треде,
  «догонялка» старше 10 минут после сна или разрыва сети.
- Мигание кнопки на панели задач и бейдж с числом непрочитанного (красный — есть упоминания).

### Трей и автозапуск
- Значок в трее меняется: обычный, есть непрочитанное (синяя точка), есть упоминания (красная),
  «Не беспокоить» (серый). В подсказке число непрочитанного.
- Меню трея: открыть, «Не беспокоить» (1 ч / 8 ч / до завтра 9:00 / пока не выключу),
  настройки уведомлений, автозапуск, сворачивание при закрытии, выход.
- Крестик окна по умолчанию сворачивает в трей. Это настраивается.
- Автозапуск с Windows, по умолчанию свёрнутым в трей.
- Повторный запуск ярлыка не открывает вторую копию, а показывает уже открытое окно.

### Звук и «Не беспокоить»
- Громкость звука и кнопка «Проверить».
- Звук только для упоминаний и личных сообщений.
- Опция «Показывать текст сообщения» — для общих экранов.
- Ручной режим «Не беспокоить» с таймером. Можно пропускать упоминания и личные сообщения.
- Тихие часы по расписанию (например, 19:00–09:00) и выходные целиком.

Всё это находится в «Настройки → Notifications».

### Треды как в Discord
- Ответы в тредах больше не попадают в общую ленту: она только для основного разговора.
- Под корневым сообщением плашка «N ответов · кто ответил последним · когда» с отметкой непрочитанного.
- Тред открывается в боковой панели (на узком экране — на весь экран) со своим полем ввода,
  ответами, реакциями, редактированием и вложениями.
- Кнопка «Треды» в шапке комнаты открывает список тредов комнаты (загружается с сервера):
  фильтры «Все» и «Мои», счётчики непрочитанного. На кнопке — число тредов,
  где у вас есть непрочитанное.
- Значок треда на сообщении («Начать тред») открывает новую панель вместо ответа в общем поле.
- Ответы в чужих тредах без упоминаний не подсвечивают комнату в списке.
  «Отметить прочитанным» и Esc отмечают и треды.

### Треды в списке комнат
- Под каждой комнатой слева показываются её активные треды (как в Discord): название — начало корневого
  сообщения, у непрочитанных значок и счётчик. Не больше трёх, самые свежие по последнему сообщению сверху, остальные по кнопке «Показать ещё N».
  Весь список сворачивается компактной кнопкой «⌄ N» в строке комнаты (состояние запоминается, при
  непрочитанных тредах в свёрнутом виде число подсвечивается).
- Тред, в котором никто не писал больше недели, из списка пропадает (проверка раз в 5 минут).
  Треды старше хвоста синка догружаются с сервера по одному запросу на комнату, очередью.
- Клик по треду открывает его на всю область комнаты. Кнопка в шапке треда сворачивает его в боковую
  панель и обратно, клик по самой комнате возвращает общую ленту.
- Отключается в «Настройки → General → Треды в списке комнат».

### Опросы
- «+» в поле ввода → «Опрос»: вопрос, 2–20 вариантов, «несколько ответов», «скрыть результаты до завершения».
  Работает и в поле ввода треда.
- Формат совместим с Element (MSC3381, `org.matrix.msc3381.poll.*`): опросы из Element видны у нас и наоборот.
  Читаются и стабильные типы `m.poll.*`.
- Голосование, живые проценты, завершение опроса автором или модератором. Поздние голоса не считаются,
  испорченные бюллетени игнорируются.

Технически включён `threadSupport` в matrix-js-sdk. **При первом запуске новой версии
кэш синхронизации сбрасывается один раз**: клиент заново загрузит комнаты. Ключи шифрования,
вход и настройки не затрагиваются.

### Исправлено попутно
- Первый ответ из панели нового треда не создавал тред на клиенте: панель оставалась пустой, пока не
  перезагрузишь приложение. Теперь тред заводится при открытии панели.
- Корневое сообщение могло оказаться в конце ленты треда (SDK сравнивает время получения, а не отправки).
  Теперь корень всегда первый.
- Два одновременно открытых поля ввода (комната и тред) роняли приложение:
  все редакторы Slate делили один объект начального значения
  (`cinny/src/app/components/editor/Editor.tsx`).
- Автообновление из апстрима выключено (feature `updater` убран из `default`, артефакты
  апдейтера не собираются). Иначе апстрим перезапишет корпоративную сборку.

## Репозитории

- [`agpopov/cinny`](https://github.com/agpopov/cinny) — веб-клиент, ветка `corp`.
- [`agpopov/cinny-desktop`](https://github.com/agpopov/cinny-desktop) — обёртка Tauri, ветка `corp`.
  Сабмодуль `cinny` закреплён на конкретном коммите форка `cinny`.
- Homeserver `matrix.05.team` прописан в `config.json` (`allowCustomHomeservers: false`).
- Апстрим: remote `upstream` в обоих репозиториях (`cinnyapp/cinny`, `cinnyapp/cinny-desktop`).

### Доработка
1. Правки веба: коммит в `cinny` (ветка `corp`), push.
2. В `cinny-desktop`: `git add cinny && git commit` — фиксирует новую версию сабмодуля, push.
   Без этого сборка возьмёт старый коммит веб-части.

### Новая версия апстрима
Раз в неделю workflow `upstream-check.yml` сравнивает теги `cinnyapp/cinny` и `cinnyapp/cinny-desktop`
с нашими ветками и, если вышла новая версия, заводит issue с меткой `upstream`.

Накатить обновление:
```
scripts/sync-upstream.sh            # сливает последние релизные теги в corp обоих репозиториев
scripts/sync-upstream.sh --push     # то же + push обоих репозиториев
scripts/sync-upstream.sh v4.13.0 v4.13.0   # конкретные теги cinny и cinny-desktop
```
Скрипт сливает теги `vX.Y.Z`, а не `dev`, обновляет ссылку на сабмодуль, проверяет линтером изменённые
нами файлы и собирает веб-часть. Устаревшие апстримовские workflow, которые мы удалили, при слиянии
остаются удалёнными. Конфликты в наших файлах (`RoomTimeline.tsx`, `RoomInput.tsx`, `desktop.rs` и т. д.)
скрипт не разрешает: он останавливается, правьте вручную, `git commit`, повторите запуск.
После слияния соберите проверочный `.exe` (Actions → Corp build → Run workflow), затем выпускайте версию.

## Сборка

**В CI (GitHub Actions).** `.github/workflows/corp-build.yml` на `windows-latest` собирает `.msi` и
`-setup.exe`. Запуск: вручную (Actions → Corp build → Run workflow) — артефакты в прогоне,
или пуш тега `v*` — тогда файлы ещё и прикладываются к GitHub Release.

**Выпуск:** `npm run bump -- X.Y.Z` (обновляет версию в `package.json`, `Cargo.toml`, `tauri.conf.json`),
коммит, `git tag vX.Y.Z && git push --tags`. Версия должна быть числовой: MSI не принимает суффиксы.

Для GitLab остался `.gitlab-ci.yml` с теми же заданиями (нужен Windows-раннер с тегом `windows`).

**Локально на Windows:**
```
cd cinny && npm ci && cd ..
npm ci
npm run tauri build
```
Для разработки: `npm run tauri dev`.

## Раскатка
- `.msi` подходит для групповых политик или SCCM. `.exe` (NSIS) ставится без прав администратора.
- Идентификатор приложения остаётся `in.cinny.app`. Поэтому при установке поверх обычного Cinny
  сохраняются вход и данные, а уведомления подписываются как «Cinny».
- Если пользователь запускает приложение без установщика (портативно), имя для уведомлений
  регистрируется само при старте (`HKCU\Software\Classes\AppUserModelId\in.cinny.app`).
- Если уведомления не появляются, проверьте «Параметры Windows → Система → Уведомления → Cinny»
  и режим «Фокусировка внимания»: Windows сама глушит уведомления в этом режиме.

## Требования к серверу
Треды и счётчики по тредам требуют поддержки Matrix 1.4+ (threads API, тредовые отметки
о прочтении). Synapse начиная с 1.70 подходит. На старом сервере треды работают частично:
список тредов может не загрузиться, отображение в ленте при этом работает.

## Проверка
- Rust-часть проверена компиляцией под `x86_64-pc-windows-msvc` (debug и release).
- Веб-часть: TypeScript без новых ошибок относительно апстрима, ESLint без ошибок, `vite build`.
- Сквозной тест `tests/e2e/threads_notifications.py` (25 проверок) на реальном Synapse
  с подменой IPC Tauri. Он проверяет треды, отправку в тред, уведомления (в том числе отсутствие
  уведомлений для чужих тредов), счётчик, DND из трея, клик по уведомлению, список тредов
  и настройки. Запуск: поднимите Synapse на `127.0.0.1:8008` с пользователями `alice` и `bob`
  (пароль `pass123`), раздайте сборку `cinny/dist` через `tests/e2e/spa_server.py`
  с `config.json`, где `homeserverList: ["http://localhost:8008"]`, затем выполните
  `python3 tests/e2e/threads_notifications.py`. Опросы и треды в списке комнат: `tests/e2e/polls_threads_nav.py`
  (на Synapse с открытой регистрацией; переменная `APP_URL` задаёт адрес сборки).
- Нативный показ тоста, трей и автозапуск проверяются только на живой Windows: в CI
  их проверить нельзя.

## Что не входит
- Остальной интерфейс Cinny остаётся на английском. Новые элементы (треды, уведомления,
  трей) — на русском.
- Push-уведомления при закрытом приложении (FCM/APNs) — это задача для мобильных клиентов.
